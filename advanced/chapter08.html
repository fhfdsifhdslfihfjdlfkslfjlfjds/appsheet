8-1 なぜ運用設計が必要か

ここまでの7章で、プロジェクト管理アプリの機能面は完成しました。しかし、実際に社内で使い始めると、「動作が遅い」「データが増えすぎた」「誰がどこを変更したかわからない」といった運用上の課題が出てきます。本章では、こうした課題を未然に防ぐための設計を行います。

📌 本章で扱う4つのテーマ
  • Sync設定:データの同期間隔を調整してパフォーマンスを向上
  • Security Filterの副次効果:アクセス制御が実はパフォーマンスにも貢献
  • データ量の管理:不要データの削減・アーカイブ戦略
  • 運用ルール:命名規則・変更管理・バックアップの仕組み

8-2 Sync設定の最適化

AppSheet は、Google スプレッドシートのデータを一定間隔で同期(Sync)してアプリに反映します。この同期間隔を適切に設定することで、データの鮮度とパフォーマンスのバランスを取ります。

■ Sync の仕組み

AppSheet のデータ同期には2種類あります。

種類タイミング説明
手動Syncユーザーが🔄を押したとき即座に最新データを取得。確実だが手動操作が必要
自動Sync設定した間隔で自動実行バックグラウンドで定期的にデータを更新

■ 自動Sync の設定

1

左メニューの ⚙ Settings をクリックします。

2

サブメニューから 「Performance」 を選択します。

3

「Sync: App to Cloud」 セクションの各設定を確認・変更します。

4

Save をクリック。

■ 推奨設定

項目推奨値説明
Sync on startONアプリ起動時に最新データを取得。常にON推奨
Delayed syncOFFOFFにすると、データ変更のたびに即座に同期。ONにするとSyncボタンを押すまで同期を保留(通信量を節約したい場合)
Automatic updatesON約30分ごとに自動で他ユーザーの変更を取得。複数人で使う場合は必ずON
💡 Automatic updates の同期間隔について
Automatic updates をONにすると、AppSheet は 約30分ごと にバックグラウンドで自動同期を実行します。この間隔はユーザー側では変更できません。「もっと頻繁に同期したい」場合は、ユーザーに 手動で🔄ボタンを押す よう案内してください。逆に、頻繁すぎると感じる場合は Automatic updates をOFFにし、Delayed sync をON にすることで、手動同期のみの運用にできます。

8-3 Security Filterによるパフォーマンス向上

第3章で設定した Security Filter は、アクセス制御だけでなく、パフォーマンスの向上にも寄与しています。

■ Security Filter のパフォーマンス効果

比較項目Security Filter なしSecurity Filter あり
読み込むデータ量テーブル全件(例:1000行)条件に合う行だけ(例:50行)
同期時間長い短い
アプリの体感速度データ量に比例して遅くなる一定の速さを維持
Virtual Column の計算量全件分を計算取得した行だけ計算

つまり、Security Filter は 「セキュリティの仕組み」であると同時に「パフォーマンス最適化の仕組み」 でもあります。メンバーが自分のタスクだけを表示する設計は、セキュリティだけでなく、アプリの動作速度にも好影響を与えます。

📌 Slice と Security Filter のパフォーマンスの違い
  • Security Filter:サーバー側で絞り込み → 端末にデータを送る前に削減 → 高速
  • Slice:端末にデータを送った後にフィルタ → データ量自体は変わらない

パフォーマンス向上が目的なら、Slice より Security Filter のほうが効果が大きいです。ただし Security Filter は全ビューに影響するため、「管理者には全件を見せたい」場合は OR 条件で管理者を除外する設計(第3章)が必要です。

8-4 データ量の管理とアーカイブ

AppSheet は Google スプレッドシートをデータソースとして使うため、スプレッドシートの行数が増えるほどパフォーマンスが低下します。長期運用を見据えたデータ管理戦略を立てておきましょう。

■ AppSheet のデータ量の目安

データ量体感速度推奨アクション
〜500行🟢 快適特に対策不要
500〜2,000行🟡 やや遅いSecurity Filter の活用、不要カラムの非表示
2,000〜5,000行🟠 遅いアーカイブの検討、Sync 間隔の調整
5,000行〜🔴 非常に遅いアーカイブの実施、データソースの変更検討

■ アーカイブの方法

完了したプロジェクトのタスクやコメントは、一定期間が経過したら別シート(アーカイブシート)に移動することで、アクティブなデータ量を抑えられます。

1

Google スプレッドシートに 「タスク_アーカイブ」 シートを新規作成します(カラム構成はタスクシートと同じ)。

2

完了日が 3ヶ月以上前 のタスク行を、タスクシートからアーカイブシートに切り取り→貼り付けで移動します。

3

AppSheet 側で Sync(🔄) を押すと、移動した行がアプリから消えます。

⚠️ アーカイブ前の注意
  • アーカイブ対象のタスクに紐づくコメントも一緒にアーカイブしてください(Is a part of? の関係上、親だけ消すとエラーの原因になります)
  • アーカイブ後は プロジェクトの進捗率が変わります(タスク数が減るため)。完了プロジェクト自体もアーカイブするのがおすすめです
  • スプレッドシートの操作なので、AppSheet エディタではなく Google スプレッドシート上で行います

■ その他のパフォーマンス改善策

改善策効果
不要な Virtual Column を削除再計算の負荷を軽減
ビューの Column order で表示カラムを絞る描画の負荷を軽減
使わないビューを削除 or Hide不要な再描画を防止
画像カラムの使用を最小限にデータ転送量を大幅削減

8-5 運用ルールと命名規則

アプリが複雑になるほど、「誰が何をどう管理するか」のルールが重要になります。チームで運用する前に、基本ルールを決めておきましょう。

■ ① 命名規則

テーブル・カラム・Slice・ビュー・Format Rule の名前に一貫性を持たせると、メンテナンスが楽になります。

対象命名規則例
テーブル日本語、単数形メンバー / タスク / プロジェクト
カラム日本語、簡潔にプロジェクトID / 担当者 / 期限
Virtual Column日本語、計算内容がわかる名前残日数 / 期限ステータス / 進捗率
Slice「何が表示されるか」がわかる名前マイタスク / 期限超過タスク / 進行中プロジェクト
ビューSlice と同じ名前 or 用途+形式マイタスク / ステータス別タスク数 / 管理者ダッシュボード
Format Rule「対象_条件」形式優先度_高 / 期限超過_未完了 / プロジェクト_完了

■ ② 変更管理

AppSheet アプリの設定変更は、スプレッドシートのデータとは別に管理する必要があります。

やるべきこと具体的な方法
変更前のバックアップ大きな変更前に スプレッドシートのコピーを作成(ファイル → コピーを作成)
変更履歴の記録スプレッドシートに「変更履歴」シートを作り、日付・変更内容・変更者を記録
テスト環境の確保本番アプリを コピー して、テスト用アプリで先に検証してから本番に反映

■ ③ アプリのコピー方法

テスト環境を作るには、アプリをコピーします。

1

AppSheet エディタの左メニュー上部にある アプリ名の横の「⋮」メニュー(または右上のメニュー)をクリックします。

2

「Copy app」 を選択します。

3

「Copy data」をオンにすると、スプレッドシートもコピーされます(テスト用にはオン推奨)。

4

コピーされたアプリで変更をテストし、問題なければ本番アプリに同じ変更を適用します。

💡 「Copy data」のオン/オフの使い分け
  • Copy data = ON:テスト用。データも含めてまるごとコピー。テスト後に削除してOK
  • Copy data = OFF:同じデータソース(スプレッドシート)を共有する別アプリを作る場合。注意:元のデータに影響を与える可能性あり

■ ④ バックアップ

Google スプレッドシートはバージョン履歴機能で過去のデータを復元できますが、定期的にコピーを取っておくとより安全です。

バックアップ方法頻度メリット
バージョン履歴(自動)自動Google ドライブが自動保存。数ヶ月前のデータも復元可能
ファイルのコピー(手動)月1回特定時点のスナップショットとして確実に保存
xlsx ダウンロード(手動)四半期に1回Google ドライブ以外の場所にも保存できる

8-6 動作確認とまとめ

■ 確認チェックリスト

  • Settings → Performance で Automatic updates がON、Sync on start がONに設定されている
  • タスクテーブルに Security Filter が設定されている(第3章で実施済み)
  • スプレッドシートのデータ量が 5,000行を大幅に超えていない
  • 命名規則が統一されており、Slice / ビュー / Format Rule の名前から内容が推測できる
  • 本番アプリのコピー(テスト用)の作成方法を理解している
  • スプレッドシートのバージョン履歴の確認方法を理解している

■ 第8章のまとめ

No.テーマポイント
