9-2 よくあるトラブルと解決策(Q&A)

上級編のアプリ構築で遭遇しやすいトラブルをQ&A形式でまとめます。困ったときのリファレンスとしてご活用ください。

Date型同士の引き算が Number にならない
[期限] - TODAY() の結果は Duration型 になります。Number型で日数を取得するには HOUR([期限] - TODAY()) / 24 のように、HOUR() で時間に変換してから 24 で割る 必要があります。(第4章)
ROUND() で小数桁数を指定するとエラーになる
AppSheet の ROUND() は 引数1つだけ(整数への丸め)です。Excel のように ROUND(x, 3) とは書けません。代わりに ROUND(x * 1000) / 1000 のように「掛けて→丸めて→割る」手法を使います。(第4章)
Number型同士の割り算が 0 になる
AppSheet は 整数同士の割り算の結果も整数に切り捨てる 仕様があります。1 / 5 = 0 になります。本マニュアルでは 先に * 100 してから割る 方法で回避しています(([完了タスク数] * 100) / [タスク数])。(第4章)
Security Filterを設定したのにタスクが全件表示されない(0件になる)
USEREMAIL() をテスト用アドレスに書き換える際、式の中の2箇所を両方とも書き換える 必要があります。片方だけ書き換えると、条件判定が正しく動作しません。テスト後は必ず USEREMAIL() に戻してください。(第3章)
Format Rule を設定したらテキストが消えた
Text color を白(#ffffff)に設定すると、背景色がない部分でテキストが見えなくなります。Text color には 赤やオレンジなど白以外の色 を使ってください。Icon を設定した場合は、対象カラムの値がアイコンに置き換わります。(第6章)
Chart View でステータスが Chart columns に表示されない
Chart type が piechart(通常)だと、Chart columns に数値カラムしか選べません。カテゴリ別の件数集計をしたい場合は、Chart type を aggregate piechart(集計付き円グラフ)に変更してください。(第5章)
Slice の作成場所が分からない
現在の AppSheet では、Data → テーブル名の右に表示される「+」アイコン → 「Create a new slice for テーブル名」ボタン から作成します。以前あった「Data → Slices」メニューは現在のUIには存在しません。(第5章・第7章)

9-3 横展開アイデア ─ 他業務への応用

上級編で学んだスキル(Security Filter / Dashboard / Slice / Format Rule / 運用設計)は、プロジェクト管理以外の業務アプリにも応用できます。ここでは横展開のアイデアを紹介します。

💼
営業案件管理
テーブル: 顧客 / 案件 / 商談履歴 / 担当者
Security Filter で営業担当ごとの案件を制限。Dashboard で売上パイプラインを可視化。
👥
採用管理
テーブル: 候補者 / 選考 / 面接官 / ポジション
Slice で「今週の面接予定」を抽出。Format Rule で選考ステータス別に色分け。
📞
問い合わせ管理
テーブル: 問い合わせ / 顧客 / 担当者 / 対応履歴
Security Filter でサポート担当ごとの案件を制限。期限超過Sliceで未回答を管理。
📚
教育研修管理
テーブル: 研修 / 受講者 / 講師 / 出席記録
Chart View で受講率をグラフ化。Slice で「自分の研修一覧」を表示。
💡 横展開のコツ
  • まず テーブル構成(ER図) を紙に書いてから AppSheet に取りかかる
  • Ref(親子関係) を先に設計すると、Related カラムや集計が自然と使える
  • 上級編のプロジェクト管理アプリを テンプレートとしてコピー し、テーブル名とカラムを差し替えるのが最も効率的

9-6 おわりに

🎉

上級編 全9章 修了おめでとうございます！

初級編・中級編・上級編のすべてを修了したあなたは、
AppSheet で本格的な業務アプリを設計・構築・運用できるスキルを身につけました。

上級編では、5テーブル構成のプロジェクト管理アプリを通して、Security Filter によるアクセス制御、Virtual Column と SELECT/COUNT による集計、Dashboard View による可視化、Format Rule による UX 改善、そして運用設計とパフォーマンス最適化まで、業務アプリに必要なスキルを一通り網羅しました。

AppSheet は「ノーコード」ですが、上級編で扱ったようなテーブル設計、関数の組み合わせ、アクセス制御の考え方は、プログラミングの世界でも通用するアプリケーション設計の基本スキルです。このマニュアルで身につけた「設計 → 実装 → テスト → 運用」のサイクルは、どんな開発ツールでも活かせます。

ぜひ、ここで学んだスキルを 自社の業務課題に応用 して、チームの生産性向上に貢献してください。

💡 最後のアドバイス
  • 小さく作って、大きく育てる:最初から完璧なアプリを目指さず、まず最小限の機能で使い始め、フィードバックを得ながら改善していく
  • ユーザーの声を聞く:アプリの開発者である自分だけでなく、実際に使うメンバーの意見を取り入れる
  • 壊れたら直す:エラーが出ても焦らない。本マニュアルの Q&A を参照し、一つずつ原因を切り分ける
  • 仲間を増やす:社内に AppSheet を使える人が増えれば、自分の負担も減り、より多くの業務が改善できる
